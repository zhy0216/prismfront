## M0 spike 实测新增的三条（2026-08-07）

### ⚠️ R-M0-1 · `turbo boundaries` 的 tag deny 对外部 npm 包完全无效

**实测**（M0/S3，含隔离对照仓）：`turbo.json` 里 `boundaries.tags.pure.dependencies.deny`
的六项 `colyseus` / `colyseus.js` / `phaser` / `vite` / `zod` / `@types/bun`
**全是死配置**。turbo 2.10.8 的依赖图里只有 workspace 包节点，deny 列表里凡不是 workspace
包名的字符串匹配不到任何节点，就被静默当成 no-op —— **turbo 不会警告这条 deny 没匹配上任何东西**。

判别实验：把 `phaser` 真加进 `packages/engine` 的 `dependencies` 并 `bun install`，
`import "phaser"` 原样保留、`pure` tag 原样保留 → `turbo boundaries` **绿，exit 0**。
同一份 `turbo.json` 里换成 workspace 包名（`@prismfront/engine`）立刻报
``Package `@prismfront/engine` found with tag listed in denylist``。

**好消息**：`no-rules.dependencies.deny` 的两项都是 workspace 包名，
所以 `apps/client` 那道围栏是**真的**，而且是 manifest 级（写进 package.json 就红，比 import 级更严）。

**当前实际守卫与它们的缺口**：

| 层 | 机制 | 有效范围 | 缺口 |
|---|---|---|---|
| import 语句 | `packages/*/biome.json` 的 `noRestrictedImports` | **只拦裸包名** | `import "zod/mini"` / `import "phaser/dist/phaser.js"` 全绿 |
| import 语句 | boundaries 的「未声明依赖」检查 | 能把 subpath 归约到包名 | **只在该依赖没进 `dependencies` 时成立** |
| manifest | 无 | — | **完全没有** |

**已验证的洞**：往 `packages/engine/package.json` 加 `"colyseus": "catalog:server"`，
`bunx turbo typecheck lint` + `bunx turbo boundaries` **三道闸全绿、零告警**。
§6.3「engine 的 `dependencies` 永远为空」这条铁律目前**没有任何机器强制**。

**处置**：本轮决定**只登记不改代码**（不动 §3.1 逐字块、不加 CI 脚本）。
建议的补法（留给 M1/M2 决定是否做）：加一条 CI 断言 —— `packages/*/package.json` 的
`dependencies` 只允许 `workspace:*`。它能**同时堵上 manifest 洞与 subpath 洞**
（依赖不进 manifest，subpath import 就会被 boundaries 的未声明依赖检查拦下）。

### ⚠️ R-M0-2 · `bunfig.toml` 不被子目录继承，§7 的覆盖率闸门当前是纸面条款

**实测**：bun 1.3.14 只从 **cwd** 读 `bunfig.toml`（外加 `~/.bunfig.toml`），不往上层找。
而 `turbo test` 跑各包的 `test` 脚本时 cwd 是**包目录** —— 所以根 `bunfig.toml` 的
`preload` / `coverage` / `coverageThreshold = { line = 0.8 }` 在 `bunx turbo test` 下
**一律不生效**（沙盒复现：cwd=根时 preload 执行且打覆盖率表，cwd=子目录时两者都没有）。

架构文档 §7 给了 `bunfig.toml` 全文，本轮按「逐字采用」原样保留，没有改。

**M2 落测试时必须三选一**：各包各放一份 `bunfig.toml`；或包级 `test` 脚本显式带
`--preload` / `--coverage`；或改成从仓库根跑一次 `bun test`。

### ⚠️ R-M0-3 · Phaser 4 的 ESM 产物没有 default 导出，但类型说有

**实测**：`phaser@4.0.0` 的 `exports.import` 指向 `dist/phaser.esm.js`（webpack 单文件包），
**只有具名导出**；而 `types/phaser.d.ts` 结尾是 `export = Phaser`。
我们 `tsconfig` 的 `module: "preserve"` 隐含 `esModuleInterop`，于是
`import Phaser from "phaser"` **能干净地过 `tsc`**，一进浏览器就炸：

```
Uncaught SyntaxError: The requested module '/node_modules/.vite/deps/phaser.js'
does not provide an export named 'default'
```

**类型检查完全拦不住这条。** [M10](./M10-Phaser客户端.md) 的硬规矩：
全仓统一 `import { Game, Scene, AUTO } from "phaser"`，**禁 default 导入**。
