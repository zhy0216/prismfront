## spike 实测结论（2026-08-07）

**「花半天验证，或者花两周后返工」这句话兑现了** —— 三个 spike 各推翻了一件事。

### S1 · Colyseus × Bun → 选型可用，但文档前提是错的

- `@colyseus/bun-websockets@0.17.13` 在 Bun 1.3.14 下**开箱可用**，echo 往返 0.84–0.96ms。
  `bun-serve-express` 那层 shim 不在请求热路径上。**退路（`@colyseus/ws-transport`）不启用。**
- **架构文档 §1.1 选 `colyseus.js@0.16.22` 的前提是错的**：它是 0.16 线的**旧包名**，
  0.17 线官方 SDK 叫 `@colyseus/sdk`。`colyseus.js` 连 0.17 服务端会挂在 matchmaking
  座位预定的 JSON 信封上（与 schema 无关）。
  → **已改 `catalogs.client` 为 `@colyseus/sdk@0.17.43`**，它依赖 `@colyseus/schema@^4.0.7`
  与服务端同 major，**schema 3/4 裂口从依赖层面根除**，peer 警告消失。
- 决策 #1「不用 Schema」成立，`serializerId === "none"` 是它的机器可验证哨兵。
- 顺带挖出 §13 坑 7 的三条实测细节（M9 必读，已写进 `spike/room.ts` 注释）：
  `allowReconnection` 超时时 reject 的是**布尔 `false` 不是 Error**；
  0.17 的 `onLeave` 第二参是 close code 不是 `consented`；
  0.17 新增 `onDrop`，**同时定义 `onLeave` 与 `onDrop` 会让非自愿断线只进 `onDrop`**。

### S2 · Vite 8 × Bun × Phaser 4 → 两条退路都不启用

浏览器实测方块渲染成功（WebGL / ANGLE Metal，120fps，console 零 error）。
**不必回退 `phaser@3.90`，也不必把客户端 dev 迁回 Node。**
挖出一个类型系统拦不住的陷阱（Phaser 4 无 default 导出但 `.d.ts` 说有）与两个 Bun 毛刺，
全部记入[风险登记册](../风险登记册.md) R-M0-3 / R-M0-2。

### S3 · boundaries 生效 → **围栏是假的，这是本次最重要的发现**

boundaries 确实会变红，但**红的原因是「未声明依赖」检查，不是 tag deny**。
判别实验：把 `phaser` 真加进 `packages/engine` 的 `dependencies` 后，`pure` tag 原样、
`import "phaser"` 原样 → **boundaries 绿，exit 0**。

`turbo.json` 里 `pure.dependencies.deny` 的六个**外部包名全是死配置**
（turbo 的依赖图只有 workspace 包节点，匹配不上就静默 no-op，且不会警告）。
§2.2 禁令 2 与 §6.3「engine `dependencies` 永远为空」**目前没有任何 manifest 层机器强制**。

本轮决定**只登记不改代码**（不动 §3.1 逐字块、不加 CI 脚本）。
详见[风险登记册](../风险登记册.md) **R-M0-1**，含建议补法。

### 修掉的假绿（对抗式校验挖出来的）

- `bunx turbo lint` 原本执行 0 个任务并 **exit 0** —— 无包定义 `lint` script，
  Biome 从未在 CI 里跑过，六份 `biome.json` 全是死配置。已给 8 个包加 `"lint": "biome check ."`。
- `bun.lock` 264/264 条 URL 指向 `registry.npmmirror.com`（本机镜像配置被固化进锁文件）。
  已重新生成为**零硬编码 URL** 的可移植形式。
- `packages/engine` 缺 §6.1 点名要禁的 `Math.random` 守卫（`noRestrictedGlobals` 禁不了成员表达式）。
  已改用 `nursery/noJsRestrictedProperties`，实测报红。
