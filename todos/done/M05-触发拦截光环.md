      「单次结算栈深度 256」），专门测试新建在 `resolve/__tests__/deathrattle-loop.test.ts`。
  - [x] **先验证再动手**：实测三条路径（`runActs` 直驱 / `apply` 的自动相位 /
        战斗第 ④ 步开闸）撞上亡语环时**都**在有界步数内抛 `ResolutionLoopError`，
        没有一处挂死 —— 因为亡语只入栈不立即执行（时序规则 2），必然一步一次地
        经过 `resolve()` 那个计数的 `while`。**所以不新增亡语专用上限。**
        反向实验：把那道 guard 拿掉（或改成按栈**高度**判），同一批测试直接把

  - [x] ★ **「合法的深链」与「无限循环」分得开**：一条亡语召唤一个带亡语的随从
        完全合法（复制品活着就收口）、64 层亡语接力也照跑；上限落在**同一次结算的
        弹栈次数**上，与套了几层亡语无关。两条正向测试各钉一头。
  - [x] 环由**组合**产生，不能靠禁写法防：「亡语召唤自己」+「友军血量上限 −1 的光环」
        两张各自合法的卡摆在一起就是环。同理，一条**有限但超预算**的长链（512 层）
        也照样被截断 —— 引擎不做环检测，上限管的是预算。
  - [x] ★ **失败形态拍板：抛错，不截断**（维持 M2 写在 `rules/apply.ts` `@throws` 上的
        取舍，理由补全写在测试文件头）。截断 = 一半亡语跑了一半没跑，而这份说不通的
        状态会照常进快照 / 回放。抛错则：整段结算有界（≤ 256 次弹栈）、进程照常响应、
        事件流挂在错误对象上（`unit_summoned.cardId` 直接指认罪魁卡）。
  - [x] 顺带钉住一条以前只写在注释里、没测过的性质：`apply()` 是**先 clone 再跑**的，

落点：`packages/cards/src/keywords/`（范式 + `__tests__/keywords.test.ts`，8 条）。

它的测试里只写得出手抄的 IR 字面量，验不了「编写层写不写得出来」。

《数值基准》§6 的 G06 / R05 / R06 仍归 M11。

★ **三条自洽性没有为它们写任何特判** —— T6 只新增了上面那两个文件，
