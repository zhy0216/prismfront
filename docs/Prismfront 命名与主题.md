# Prismfront 命名与主题设定

> 定名（2026-08-05）：中文 **《棱镜前线》**，英文 **Prismfront**（单词、首字母大写，
> 不写作 PrismFront）。备选过程存档：Prismata 路线的 Chromata / Synchroma /
> Trichroma / Stoicheia / Krasis 落选但保留在案，未来做资料片或衍生模式可复用。

## 1. 名字含义

- **棱镜（Prism）**：白光经棱镜分为三色——红蓝绿正是光的三原色（RGB），
  对应游戏的三色体系；融合卡即"合光"
- **前线（front）**：9 格单路战线；也呼应行动交替、对撞结算的阵地战气质
- 与 Prismata（Lunarch Studios）区隔：一个是"众棱镜"（希腊语复数），
  一个是"棱镜+前线"复合词，字形字义均拉开；正式发布前仍需例行商标核查

## 2. 光学主题系统（机制 → 隐喻的完整映射）

| 机制 | 光学隐喻 |
|---|---|
| 英雄色门（打出限制） | 英雄是**光源**：场上没有红色光源，就发不出红色的光 |
| 英雄专属卡（组牌限制） | 每盏光源有自己的**谱线**：不把这盏灯装进阵列，就取不到它的谱线 |
| 英雄阵亡缺席一回合 | 光源熄灭，需要时间重新点亮 |
| 融合卡（双色） | **加色混合**：两束光叠加成新色 |
| 全场同时结算 | 光束交汇对撞，瞬间完成 |
| 战斗方向 / 斜打 | 光的射线与折射 |
| 9 格战线 | 谱线——离散位置上的彩色线条 |
| 水晶经济 | 棱镜介质 / 光晶 |
| 基地（30 血） | 主棱镜 / 光核（可选术语皮肤，机制名不变） |

主题不是皮，它在替玩家做规则记忆：「为什么没有红英雄就不能出红牌？」——
「因为没有红光源」。一句话讲完色门规则。

**谱线与光源是两件事，隐喻必须分开讲**（对应构筑限制与打出限制的解耦，规范 §11.1）：
「为什么这张牌我带不了？」——「你没装这盏灯」（组牌看归属）；
「为什么这张牌打不出？」——「场上没有这个颜色的光」（打出只看颜色）。
灯灭了，它的谱线不会从牌组消失；只要还有同色的光，照样打得出。

## 3. 色彩语言规范（信息设计红利）

加色混合天然给出融合卡的第二级色彩语言，卡框直接采用：

| 组合 | 卡框色 | 恰好是 |
|---|---|---|
| 红 + 绿 | **黄（Yellow）** | CMY 印刷三原色之一 |
| 红 + 蓝 | **品红（Magenta）** | 同上 |
| 蓝 + 绿 | **青（Cyan）** | 同上 |
| 红 + 蓝 + 绿（未来） | **白（White）** | 三色齐聚，留给未来的顶级卡位 |

RGB 融合出 CMY——玩家一眼识别融合对，无需读文字。UI/卡面设计从第一天遵守。

## 4. 工程命名规范

- 仓库：`prismfront`
- 包：`@prismfront/engine`、`@prismfront/cards`、`@prismfront/shared`、
  `@prismfront/server`、`@prismfront/bot`（替换此前文档中的 `@cardgame/*` 占位）
- IR bundle id 前缀：`prismfront-core@...`
- 卡牌集合码建议：基准集 `PF1`（替代示例中的 BASE_/CORE_/GRID_ 前缀，
  正式建卡时统一为 `PF1_R01` 式）
- 线上标识（注册前逐一核查）：域名 `prismfront.gg / .com`，
  社交 handle `prismfront` / `playprismfront`
