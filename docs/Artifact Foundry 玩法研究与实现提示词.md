# Artifact Foundry(Artifact 2.0 beta)玩法研究与实现提示词

> 深度研究结论(2026-07-17):5 个搜索角度、18 个来源、80 条声明中对抗性核实 25 条(23 确认 / 2 证伪)。
> 权威来源:Valve 官方 Steam 新闻(Foundry appid 1269260、Classic appid 583950)、Dot Esports、PCGamesN、PC Invasion、artifact fandom/artifactwiki(1.0 基线)。

## 一、研究结论摘要

### 已证实的 Foundry(2.0)核心机制
1. **全局行动流**:移除 1.0 的逐路顺序行动。双方在任意路交替行动,直到连续两次 pass 进入战斗;先手权按"回合"持有而非按"路";"夺取先手"类法术更名为 Quick;战斗按路依次结算——奇数回合从左到右,偶数回合从右到左;卡牌默认只影响单路,除非另有说明。(3-0 核实 ×4)
2. **单一全局法力池**:起始 3 点,每回合 +1;每次行动(含技能、物品使用)至少消耗 1 费,无法免费拖延回合。(3-0 ×3)
3. **护甲重做 + Feeble**:1 点护甲挡 1 点伤害,护甲是**每回合刷新的消耗型格挡池**(非 1.0 的永久每击减伤);Feeble 关键词:攻击 Feeble 单位的每个单位将溢出伤害打向塔。(3-0 / 2-1)
4. **去随机化**:除洗牌外几乎全部随机元素被移除;攻击箭头默认笔直向前,仅可被卡牌效果临时改向;相比 Classic 新增 100+ 卡牌、20+ 英雄。(3-0 ×2)
5. **兵线结构**:保留三路,但每路 5 个固定槽位(1.0 无上限);槽位位置固定,加入单位不挤动他人。倾向解读为**每方每路 5 槽**(证据占优但非铁证)。(3-0 ×2)
6. **英雄部署**:玩家自主指定、按路顺序进行——先选中路英雄、再劣势路、最后安全路,逐路揭示(后选的有更多信息)。注意:"逐个英雄严格交替部署"的说法被 0-3 证伪,应实现为逐路"同时秘密选择 + 揭示"。(3-0)
7. **小兵机制**:确定性生成——每回合开始前每路生成 1 个小兵,落入最左空槽;手牌小兵由玩家选槽。Valve 2020-04 演示中基础小兵为 1/1(demo 值;1.0 近战小兵为 2/4)。(2-1 ×2)
8. **塔血**:演示中六座塔均 30 HP,Valve 明确说明"塔血取决于游戏模式"。**Foundry 最终胜利条件无存世证据**;"赢下三路中两路"的说法被 0-3 证伪。建议沿用 1.0 结构:摧毁两座塔,或一塔 + 遗迹(1.0:塔 40、遗迹 80)。(2-1 / 3-0)
9. **颜色系统保留**:有色卡只能打在有己方同色英雄的路;2020-10-29 补丁引入实验性 Multicolor Casting(同路英雄互相解锁彼此颜色),同补丁使无色卡也需要该路有英雄才能打出。(3-0)
10. **经济**:保留金币商店与可跳过的购物步骤,重做为每人 10 张物品牌组;物品牌组耗尽后随机 T1 物品售价 10/15 金;初始金币最终值 = 15(2021-03-04 补丁)。(3-0 ×2)
11. **物品装备**:2020-12-23 补丁移除武器/护甲/饰品部位——每名英雄可装备任意两件不重复物品(实验性规则,至停更未回滚)。(3-0)
12. **1.0 基线(用于填补 2.0 未证实处)**:每方 5 英雄;第 4 名回合 2、第 5 名回合 3 部署;阵亡英雄错过**恰好一次**部署阶段(N 回合死、N+2 回合重新部署);每名英雄向 40 张最低主卡组注入 3 张签名卡;有色卡需同路同色英雄。(3-0 ×2)

### 未证实 / 需自定默认值(实现时做成配置项)
- Foundry 最终胜利条件与建筑血量(默认借用 1.0 结构 + 30 血塔)
- 2.0 卡组构筑规则(卡组下限、英雄数、签名卡是否保留、起手数、每回合抽牌数)——默认借用 1.0
- 5 槽是每方还是双方共 5(默认每方 5)
- 具体卡牌数值(Foundry 精确数值无存档,demo 卡池数值为自行平衡)

### 已证伪(勿实现)
- ✗ "胜利条件是赢下三路中的两路"(0-3)
- ✗ "英雄部署为逐个英雄双方严格交替"(0-3)

## 二、给实现 Agent 的提示词(可直接复制)

```markdown
# 任务:实现 Artifact Foundry 风格的三路卡牌对战游戏(核心规则引擎 + 可玩 Demo)

## 0. 背景与交付目标

你要实现一个复刻 Valve《Artifact Foundry》(Artifact 2.0 beta,2020-2021,从未正式发布)核心玩法的卡牌对战游戏。本提示词中的规则已经过多来源核实:标注 **[证实]** 的是 Valve 官方补丁/公告确认的 2.0 规则;标注 **[默认值]** 的是资料缺失处借用 Artifact 1.0 或自行设定的值——**所有 [默认值] 必须做成集中配置项**,便于后续调整。

交付物:
1. **确定性规则引擎**(与 UI 完全分离,可 headless 运行完整对局);
2. **本地对战 Demo**:双人热座 + 简单 AI 对手,二者共用引擎;
3. **约 40 张卡池**(本文第 6 节给出全部卡牌定义)与两套预构筑卡组;
4. **单元测试**覆盖第 8 节列出的边界用例;
5. README:操作说明 + 规则速览。

技术栈:如无额外约束,建议 TypeScript(引擎为纯逻辑包),UI 用 CLI 或最小网页实现均可,以规则正确性优先、美术从简。

## 1. 对局总览

- 双人对战。棋盘为三条兵线(lane):lane0 / lane1 / lane2。lane1 为中路;lane0 是 P1 的安全路、P2 的劣势路;lane2 反之(仅影响部署顺序的语义,不影响规则)。
- 每路每方拥有:1 座**塔**(30 HP **[demo 值,证实为"随模式而变",做成配置]**)+ **5 个固定单位槽位** **[证实:每路 5 槽;"每方 5 槽"为主流解读,槽位总数做成配置]**。槽位位置固定:单位放入后不移动,新单位加入不挤动已有单位 **[证实]**。
- 某方某路的塔被摧毁后,该路暴露该方**遗迹(Ancient)**,80 HP **[默认值,借 1.0]**。
- **胜利条件 [默认值,借 1.0 结构;Foundry 最终规则无存档]**:摧毁敌方任意**两座塔**,或摧毁敌方**遗迹**(遗迹只有在其所在路的塔被毁后才可被攻击)。胜利判定实现为可替换策略(strategy/config)。
- 战斗中对位无单位的攻击打塔;塔不反击 **[默认值]**。

## 2. 资源系统

- **法力(全局单池)[证实]**:双方各自持有一个全局法力池(不分路)。回合 N 开始时刷新为 `2 + N`(即回合 1 为 3 点),每回合 +1,未用完不结转 **[结转规则为默认值]**。
- **除 pass 外的每次行动至少花 1 点法力 [证实]**:出牌、使用英雄主动技、使用物品主动效果都算行动;费用减免效果不能把实际支付降到 1 以下(clamp 到 1)**[默认值:官方曾出现负费实验卡,demo 不实现]**。
- **金币**:初始 15 金 **[证实:最终补丁值]**。击杀小兵 +1 金、击杀英雄 +5 金 **[默认值,借 1.0]**,归击杀者所属玩家;同时阵亡各自正常发赏金。金币用于购物阶段买物品。

## 3. 英雄、卡组与抽牌

以下构筑规则整体为 **[默认值,借 1.0;2.0 无存档规则]**:
- 每方 **5 名英雄**。每名英雄自带一张**签名卡**,3 份副本计入主卡组。
- 主卡组 40 张(含 15 张签名卡副本);英雄卡不在抽牌堆中,走部署序列。**物品牌组**每人 10 张,与主卡组分离 **[证实:2.0 围绕 10 张物品牌组重做商店]**。
- 起手 5 张,**每回合结束时各抽 2 张**;手牌上限 10,超出弃掉 **[默认值]**。
- Demo 直接使用第 6 节的两套预构筑卡组,不做构筑器;不强制单卡份数上限。

## 4. 回合流程(核心状态机)

每回合依次经过以下阶段。**注意:2.0 没有逐路行动/逐路结算的流程,不要按 1.0 的"每路一个行动+战斗阶段"实现。**

### 4.1 回合开始
- 刷新双方法力池(见 §2)。
- **刷新所有单位与塔的护甲池**(见 §5 护甲规则)**[证实:护甲每回合开始时刷新]**。
- 结算"每回合开始/部署阶段"类持续效果(改良、物品)。

### 4.2 部署阶段
1. **小兵生成 [证实]**:每路为每方生成 1 个基础近战小兵(1 攻 / 0 甲 / 1 命 **[demo 值,配置]**),放入该方该路**最左侧空槽**;该方该路槽满则不生成。双方同时执行,过程无随机。
2. **英雄部署**:
   - **回合 1(初始部署)[证实]**:三步流程,每步双方**同时秘密选择、然后同时揭示**:
     a. 各自选 1 名英雄放中路(lane1)→ 揭示;
     b. 各自选 1 名英雄放自己的**劣势路**(P1→lane2, P2→lane0)→ 揭示;
     c. 各自选 1 名英雄放自己的**安全路**(P1→lane0, P2→lane2)→ 揭示。
     槽位由玩家在己方该路空槽中任选。**不要实现为逐个英雄双方交替选择(该说法已被证伪)。**
   - **回合 2**:双方部署第 4 名英雄,路与槽自选 **[默认值,借 1.0]**。
   - **回合 3**:部署第 5 名英雄 **[默认值,借 1.0]**。
   - **阵亡英雄重新部署 [借 1.0,规则本身证实]**:英雄在回合 N 阵亡 → 错过**恰好一次**部署阶段 → 回合 N+2 的部署阶段重新部署,路与槽自选。(常见错误:让英雄错过两次部署——不要这样实现。)
   - 同一步内双方都要部署时,视为同时(秘密选择 + 揭示)**[默认值]**。

### 4.3 行动阶段(全局)[证实]
- 持先手的玩家先行动,此后双方**交替**行动。
- 一次行动 = 以下之一:
  - 打出一张手牌(需满足颜色规则 §7 与费用);
  - 使用一名在场英雄的主动技能;
  - 使用已装备物品的主动效果;
  - **pass**(不花费法力)。
- 行动可以指向**任意一路**(全局视角),卡牌效果默认只影响其目标所在的单路,除非卡面写明跨路 **[证实]**。
- 打出带 **Quick** 的牌:结算后行动权仍归你,可继续行动 **[Quick 关键词证实存在;效果定义为默认值]**。
- **双方连续两次 pass(你 pass、对方也 pass)→ 行动阶段结束,进入战斗 [证实]**。pass 后若对方行动了,你可以再次行动。

### 4.4 战斗阶段 [证实]
按路依次结算:**奇数回合从 lane0 → lane2,偶数回合从 lane2 → lane0**。每一路内:
1. **确定攻击目标**:每个单位的攻击箭头**默认笔直向前**,指向敌方同一槽位的对位单位;对位为空 → 攻击敌方塔(塔已毁则攻击遗迹)。箭头只能被卡牌效果**临时**改向(如 Taunt)**[证实]**。
2. **同时伤害**:本路所有单位按行动阶段结束时的攻击力快照,同时对各自目标造成伤害。
3. **护甲结算**(见 §5):伤害先消耗目标的当回合护甲池,余下扣生命。
4. **关键词结算**:Feeble / Siege / Cleave 等按 §5 定义。
5. **死亡结算**:生命 ≤ 0 的单位死亡,发放赏金;英雄进入泉水等待重生;改良/光环随即失效重算。
6. **建筑判定**:塔血 ≤ 0 → 塔被摧毁、该路遗迹暴露;每路结算完检查一次胜利条件,满足则**立即结束对局**。

### 4.5 购物阶段 [证实:保留且可跳过]
- 双方各自(互不干扰,可实现为同时)进行:可花金币购买**自己物品牌组顶部的一张物品**,或直接跳过。
- 每人每回合最多买 1 件 **[默认值]**。买到的物品进入手牌区/物品栏,装备动作在行动阶段进行(装备本身算一次行动,至少 1 费)**[默认值,与"物品使用消耗法力"的证实规则一致]**。
- **物品牌组耗尽后**:商店改为提供随机 Tier-1 物品,售价 10 或 15 金,且不再补充物品牌组 **[证实]**。这是引擎中除洗牌外唯一允许的第二个随机点,同样必须走注入的 RNG。
- UI 需在购买按钮上预览"买完剩多少金币" **[证实的官方 UI 细节,可选实现]**。

### 4.6 回合结束
- 双方各抽 2 张 **[默认值]**;超过手牌上限弃牌。
- **下回合先手**:本回合行动阶段中**先 pass 的一方**获得下回合先手 **[默认值,官方仅证实"先手按回合持有";首回合先手用注入 RNG 掷硬币]**。
- 回合数 +1,回到 §4.1。

## 5. 战斗细则与关键词

- **护甲(重做版)[证实,与 1.0 完全不同]**:护甲不是永久减伤,而是**每回合开始时刷新的格挡池**。单位有 X 点护甲 → 本回合内最多格挡 X 点伤害,被打掉的护甲**本回合内不恢复**,下回合开始时重置为当前护甲值(受装备/改良加成影响)。
  例:2 甲 5 命的单位同一回合内两次受到 3 点伤害:第一次挡 2 掉 1 血,第二次护甲池已空、掉 3 血。**不要实现成 1.0 的"每次受击都减 2"。**
- **Feeble [证实]**:攻击带 Feeble 的单位时,每个攻击者的**溢出伤害**(超出目标剩余护甲+生命的部分)打向该路目标方的塔。
- **Quick [证实存在,效果为默认值]**:结算后行动权保留(原 1.0 "夺取先手"的更名)。
- **Taunt [自定]**:战斗目标判定时,与该单位**对位及左右相邻槽位**的敌方单位箭头改指向它(临时改向的一种)。
- **Siege [自定]**:该单位战斗时无视对位,直接攻击敌方塔。
- **穿刺伤害 [自定]**:无视护甲池,直接扣生命(用于个别法术)。
- 治疗不超过生命上限;攻击力可被临时 buff/debuff,负攻击按 0 处理。

## 7. 颜色与出牌合法性 [证实]

- 有色卡(法术/生物/改良)只能打在**该路存在己方同色英雄**的路。
- 无色卡也需要该路有**任意**己方英雄。
- 物品购买不受颜色限制;装备目标是任意在场己方英雄。
- **可选规则 Multicolor Casting [证实为实验性,默认关闭,做成配置开关]**:开启时,同一路的己方英雄互相解锁彼此颜色(该路有红+蓝英雄 → 该路可打红卡和蓝卡)。

## 8. 工程要求

1. **确定性核心**:引擎为纯函数式/可回放设计——`GameState + Action → 新 GameState + Event[]`。唯一随机源是注入 seed 的 RNG(用于:洗两副主卡组、两副物品牌组、首回合先手、商店耗尽后的随机 T1 物品)。同一 seed + 同一行动序列必须产生完全相同的终局(写测试验证)。
2. **合法行动生成器** `legalActions(state, player)`:枚举当前所有合法行动(含合法目标),UI 与 AI 都只从中取行动;引擎对非法行动抛错。
3. **配置集中化**:塔血、遗迹血、每方每路槽数、初始/每回合法力、初始金币、赏金、基础小兵属性、起手/每回合抽牌数、手牌上限、胜利条件策略、Multicolor 开关……全部收进一个 config 对象,上文所有 [默认值] 与 [demo 值] 都在其中。
4. **简单 AI**:基于 `legalActions` 的启发式贪心即可,不要求搜索。优先级建议:能打死塔/遗迹的行动 > 无损换掉敌方单位 > 部署单位到能打塔的空位 > 战前 buff > pass;购物阶段买得起且有存活英雄就买。要求 AI 能与 AI 自对弈跑完整局不崩溃(以此做冒烟测试)。
5. **UI**:本地双人热座 + 人机两种模式。需要展示:三路棋盘与槽位、箭头指向、塔/遗迹血量、双方法力与金币、手牌、物品、当前阶段与先手方、战斗结算日志。CLI 或最小网页均可。
6. **必测边界用例**:
   - 护甲池:2 甲单位同回合连续吃两次 3 伤 → 掉 1 血再掉 3 血;下回合护甲重置;
   - 双方连续 pass 才结束行动阶段;pass–行动–pass 不结束;
   - 每次行动至少 1 费;费用减免 clamp 到 1;pass 不花费;
   - 英雄回合 3 阵亡 → 回合 5 部署阶段重新部署(只错过一次);
   - 小兵生成:最左空槽;槽满跳过;
   - 颜色合法性:同色英雄离场(阵亡)后该路不能再打该色卡;无色卡需任意英雄;
   - 跨路卡(暗杀、雷神之怒)可指定其他路;
   - 战斗方向:奇数回合 lane0→2,偶数回合 lane2→0(构造两路同时可致胜的局面验证顺序影响结果);
   - Feeble 溢伤打塔;Siege 直击塔;Taunt 改向;
   - 胜利判定:两塔 = 胜;一塔 + 遗迹 = 胜;遗迹未暴露时不可被攻击;
   - 物品:每英雄至多 2 件、不可重复;物品牌组耗尽后随机 T1 定价 10/15;
   - 确定性回放:同 seed 同行动序列 → 终局状态哈希一致。
```
